**Add Two-Headed Giant (#12587)**

 * Adds the Two-Headed Giant variant and the shared team turns rules it uses
 * (CR 805, 810). Teams take turns, hold priority, attack and block together.
 * A team&#x27;s combined block must be legal as a whole, and the team declares
 * again if it is not. Teammates share a life total, poison counters (15 to
 * lose), wins and losses, and may look at each other&#x27;s hands.
 * Scripts that used the active player for &quot;that player&quot; now name the
 * triggered player, so they act on one player when a whole team is active.
 * Abilities of &quot;that attacking player&quot; name the triggered attacking player.
 * &quot;A player attacks&quot; triggers whose effect does not name the attacker say
 * so with AttackingPlayer$ Player.
 * The AI treats its team as one side: whose turn it is and whose turn is
 * next, attacks, blocks, life in danger and the poison limit. An AI player
 * drops its own blocks when its team&#x27;s combined block is illegal, so the
 * team does not repeat the same block.
 * The lobby offers the variant for four players, pairs seats into teams and
 * removes variants that conflict with it. Turn and phase indicators, phase
 * stops and auto-yields follow the active team, on desktop and mobile.

**Log lands played this turn so cards that arrive later still count them (#12530)**

 * Player.playLand only did landsPlayedThisTurn++, so where a land was
 * played from existed only as the Origin parameter of the LandPlayed
 * trigger. Spider-Man 2099, Visions of Phyrexia and A-Visions of
 * Phyrexia worked around that with a Static$ True LandPlayed trigger on
 * the card that stored a count in an SVar. Casting rebuilds the card
 * from its script (GameAction.changeZone -&gt; CardCopyService.copyCard -&gt;
 * CardFactory.getCard), which resets the SVar, so a land played before
 * the card reached the battlefield was never counted.
 * Keep a per-turn list of played lands in Player, next to
 * discardedThisTurn and sacrificedThisTurn. playLand takes an LKI copy
 * before the move so the zone and owner the land was played from are
 * remembered, and adds it right after the move and before the
 * LandPlayed trigger runs. landsPlayedThisTurn is untouched. The list is
 * cleared together with the count in resetLandsPlayedThisTurn().
 * Add PlayerCountPropertyYou$LandsPlayed &lt;valid&gt; to playerXProperty to
 * count the entries that match a filter. It sits before the existing
 * unfiltered LandsPlayed check, which still returns the plain count.
 * Spider-Man 2099 now counts a land played from any zone other than a
 * hand, or a land it doesn&#x27;t own (Card.!inRealZoneHand,Card.YouDontOwn),
 * which also covers a land played from an opponent&#x27;s hand or the command
 * zone that the old Origin$ list missed. Visions of Phyrexia and
 * A-Visions of Phyrexia count Card.inRealZoneExile. The tracker trigger,
 * StoreVar, cleanup reset and stored SVar are removed from all three.
 * Co-authored-by: Agetian &lt;stavdev@mail.ru&gt;

[c9f0ab8205a69d5](https://github.com/Card-Forge/forge/commit/c9f0ab8205a69d5) Fulgur14 *2026-10-29 14:04:31*

**Fix CME when paying with a mana ability that has its own cost (#12501)**

 * Don&#x27;t redraw a payment prompt while its own mana ability runs
 * A mana ability with its own cost opens a second payment prompt. When
 * that prompt closed, the first one was redrawn on the UI thread while
 * the ability was still resolving on another thread. The redraw cleared
 * the prompt&#x27;s lock and, on a network host, walked the delta sync at the
 * same time as the ability&#x27;s own colour choice.
 * The prompt now skips that redraw while it is busy, and the ability
 * shows it again when it ends, even if it fails.
 * Run Serum Powder&#x27;s exile and draw on the game thread
 * The mulligan prompt exiled and redrew the hand on a pool thread while
 * the prompt stayed open. A network client never got the new hand until
 * it pressed Keep or Mulligan, and pressing either during the exile and
 * draw let the game carry on while they were still running.
 * The prompt now only records the choice and stops. The game thread
 * exiles and draws, then shows a fresh mulligan prompt, which sends the
 * new hand like any other prompt.
 * ---------
 * Co-authored-by: Claude Opus 5.5 &lt;noreply@anthropic.com&gt;

[49b8cdb2855529f](https://github.com/Card-Forge/forge/commit/49b8cdb2855529f) tool4ever *2026-10-19 08:12:44*

**Sound: mix effects in software instead of one device line each (#11798)**

 * Sound: mix effects in software instead of one device line each
 * javax.sound.sampled hands out a device line per Clip, and on ALSA, PulseAudio and PipeWire a line
 * is a separate application stream. SoundSystem caches one AudioClip per SoundEffectType, each
 * pooling up to 16 Clips, and nothing ever closes one -- so a session holds a stream for every
 * distinct effect it has played, times that effect&#x27;s peak concurrency. When the device stops handing
 * lines out, Clip.open() parks in DirectAudioDevice.nOpen while holding the mixer&#x27;s own monitor, and
 * the thread that asked for the sound freezes there. During a match that is the game thread.
 * Sum the samples in Java and write them to a single SourceDataLine. Each sound is converted to the
 * mixer&#x27;s format as it loads, so the mixing loop has one case and a sound set in any PCM format still
 * plays. Only the mixer&#x27;s own thread touches the device, so a slow open(), write() or close() can no
 * longer reach a caller, and the line is released after three seconds with nothing playing.
 * Measured over the 39 files in res/sound at 20 overlapping plays each, on Linux/PipeWire:
 * before                     after
 * host streams      124 and climbing, hung     1
 * when idle         never released             0
 * Memory drops with it: a pooled Clip held its own decoded copy of the sound, so an effect played
 * four times over kept four. There is now one per sound.
 * The delay that keeps a batch granular -- four lands tapping at once -- is now silence owed to each
 * new voice instead of Thread.sleep() on the caller, and a sound that fails to load leaves the clip
 * silent rather than throwing out of a call made while resolving the stack.
 * Co-Authored-By: Claude Opus 5 &lt;noreply@anthropic.com&gt;
 * Claude-Session: https://claude.ai/code/session_01Gt27YqXH2SCisddArnggbj
 * Sound: play the alternate sound system through the mixer too
 * The preference exists for people whose sound disappeared on the pooled-Clip path,
 * so it is offered as the workaround for exactly the freeze the commit before this
 * one fixes -- and it reproduced it: a thread per sound, each opening a device line
 * of its own, five copies of one sound at a time and no bound across files.
 * It now hands voices to SoftwareMixer like AudioClip does, keeping its own
 * addressing (by file path) and its own cap (five copies of a sound, one when
 * synchronized). Nothing needs a thread any more: the mixer&#x27;s thread does the
 * writing, and starting a sound is a list insertion.
 * Measured over the 39 files in res/sound, counting through Mixer.getSourceLines():
 * 78 overlapping plays reached 41 open lines with 10 still open eight seconds after
 * the last one; 780 plays now reach 1, and 0 once nothing is playing. The two drives
 * differ because the old one wedges the audio server past ~120 lines, which is the
 * bug being fixed.
 * AudioClip&#x27;s cache holds decoded samples rather than the file&#x27;s own bytes, since
 * both paths now want the same thing.
 * Co-Authored-By: Claude Opus 5 &lt;noreply@anthropic.com&gt;

**Network logging changes for readability and size (#12224)**

 * Count delta packets with a negative saving in the network log analyzer
 * The packet pattern only matched a non-negative Savings figure, so a
 * packet larger than the full state was skipped.
 * A delta can be larger than the full state on a client&#x27;s first sync.
 * The events sent with it cost more than the full-state figure allows
 * for them, because a delta serializes each event on its own while the
 * full-state figure measures them together as one list.
 * The effect on reports is marginal. In a 10-game run it dropped 11 of
 * 10,012 packets and 2.5% of delta bytes, and the overall savings figure
 * moved from 97.1% to 97.0%.
